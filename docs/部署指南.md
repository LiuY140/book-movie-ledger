# 部署指南：GitHub + Cloudflare Pages

## 整体流程

```
本地代码 → GitHub 仓库 → Cloudflare Pages 自动部署 → 公网访问
```

---

## 第一阶段：推送到 GitHub

### 1. 初始化 Git 仓库

```bash
cd "E:/WorkBuddy/个人书影管理平台"
git init
git add .
git commit -m "M1 MVP 完成：录入/CRUD/状态/筛选/评分/统计/封面代理"
```

### 2. 在 GitHub 创建仓库

1. 打开 https://github.com/new
2. Repository name：`book-movie-ledger`（或你喜欢的名字）
3. **不要**勾选 "Add a README file" / ".gitignore" / "license"（本地已有）
4. 点击 **Create repository**

### 3. 关联远程仓库并推送

GitHub 创建后会显示推送命令，复制执行：

```bash
git remote add origin https://github.com/LiuY140/book-movie-ledger.git
git branch -M main
git push -u origin main
```

> 如果使用 SSH 方式：`git remote add origin git@github.com:LiuY140/book-movie-ledger.git`

### 4. 验证

刷新 GitHub 页面，应看到完整项目代码。确认 `.env.local` **不在**仓库中（已被 .gitignore 排除）。

## 第二阶段：部署到 Cloudflare Pages

### 前置说明

| 项目 | 说明 |
|------|------|
| 适配方案 | `@opennextjs/cloudflare`（Cloudflare/Next.js 官方维护的适配器） |
| 运行时 | Cloudflare Workers（边缘网络，全球 CDN） |
| 数据库 | Supabase（不受影响，仍走 HTTPS 连接） |
| 图片代理 | 正常工作（Cloudflare Workers 原生支持 fetch） |
| 封面上传 | 正常工作（base64 存入 Supabase，不依赖文件系统） |

### 1. 安装 OpenNext 适配器（已完成）

```bash
npm install --save-dev @opennextjs/cloudflare wrangler
```

> 已安装并配置好 `package.json` 的 `preview` / `deploy` 脚本和 `wrangler.toml`。

### 2. 配置文件（已完成）

- `package.json` scripts：`preview` = `opennextjs-cloudflare build && opennextjs-cloudflare preview`，`deploy` = `opennextjs-cloudflare build && opennextjs-cloudflare deploy`
- `wrangler.toml` 已创建：`main = ".open-next/worker.js"`、`[assets] directory = ".open-next/assets"`、`nodejs_compat` 兼容标志
- `open-next.config.ts` 已创建：`defineCloudflareConfig()`

### 3. 配置环境变量

在 Cloudflare Dashboard 中设置（见下方步骤 6），需要以下变量：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxx.supabase.co` | Supabase 项目 URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_xxx` | Supabase anon key |
| `TMDB_API_KEY` | 你的 TMDB key | 影视搜索备源 |

> ⚠️ 从 `.env.local` 中复制这些值。**不要**把 `.env.local` 提交到 GitHub。

### 4. 通过 Cloudflare Dashboard 部署（推荐）

1. 登录 https://dash.cloudflare.com
2. 左侧菜单 → **Workers & Pages** → 你的项目 `book-movie-ledger` → **Settings** → **Build**
3. 修改构建配置：
   - **Framework preset**：`Next.js`（或 `None`）
   - **Build command**：`npx opennextjs-cloudflare build`
   - **Build output directory**：`.open-next`
   - **Node version**：`20`（或更高）
4. 展开 **Environment variables**，添加上方表格中的 3 个变量（如果之前已经设过则跳过）
5. 点击 **Save**，回到 **Deployments** 标签 → **Retry deployment**

首次部署约 3-5 分钟。后续每次 `git push` 到 main 分支会自动触发重新部署。

### 5. 验证部署

部署成功后 Cloudflare 会分配一个域名：
```
https://book-movie-ledger.pages.dev
```

打开验证：
- 列表页能正常加载
- 录入功能正常（能连 Supabase）
- 豆瓣封面图正常显示（图片代理生效）
- 统计页面图表正常

## 可选：绑定自定义域名

1. Cloudflare Dashboard → 你的 Pages 项目 → **Custom domains** → **Set up a custom domain**
2. 输入你的域名（如 `books.yourdomain.com`）
3. 按提示添加 CNAME 记录
4. Cloudflare 自动配置 HTTPS 证书

## 常见问题

### Q: 部署后图片代理不工作？
A: 检查 Cloudflare Pages 的 Functions 日志（Dashboard → 项目 → Functions → Real-time Logs），确认 `/api/image-proxy` 路由正常响应。

### Q: 图片代理的内存缓存在 Cloudflare 上失效？
A: 正常现象。Cloudflare Workers 每个请求可能运行在不同的 isolate 中，内存级 LRU 缓存（lru-cache）无法跨请求共享。但浏览器侧的 `Cache-Control: max-age=86400` 仍然生效，用户重复访问同一图片会走浏览器缓存。功能不受影响，只是服务端缓存命中率降低。

### Q: `git push` 后 Cloudflare 没有自动部署？
A: 检查 Cloudflare Dashboard → 项目 → Settings → Builds & deployments → 确认 Production branch 设为 `main`。

### Q: 想在本地预览 Cloudflare 构建结果？
A: 安装 Wrangler CLI 后运行：
```bash
npm install -g wrangler
npx opennextjs-cloudflare build
npx wrangler dev
```

### Q: 之前的 .next.bak* 目录怎么清理？
A: 这些是开发过程中的缓存备份，可以安全删除：
```bash
rm -rf .next.bak*
```
它们已在 .gitignore 中排除，不会推送到 GitHub。
