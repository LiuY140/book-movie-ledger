## 一、项目概述

### 1.1 项目定位

一个**只属于自己的书籍与影视记录管理平台**（单用户个人产品）。

一句话描述：**一本会生长的"书影账本"——记录与统计并重，数据 100% 归自己，无噪音，按自己的使用习惯生长。**

### 1.2 为什么做

- 豆瓣本质是社区产品，标记只是入口，个人数据难导出、评分受社区影响、噪音多；
- Notion 模板灵活但录入体验差（无元数据联想）、统计弱；
- Goodreads / Trakt 中文支持差；
- 自建平台：数据自主可控、可导出可迁移、字段按自己的习惯设计、无广告无干扰。

### 1.3 范围边界

- 仅个人使用，**不做社交/分享/社区**；
- 不做多用户协作；
- 不做移动端原生 App（桌面 Web 优先，浏览器基本可用即可）。

## 二、核心决策（已确认）

| 决策项 | 结论 |
|---|---|
| 产品定位 | 记录 + 统计并重 |
| 评分体系 | 个人十分制（0–10）+ **豆瓣评分参考**（录入时自动获取，失败手动兜底） |
| 元数据录入 | 输名自动补全 + 失败降级手动填写 |
| 存量数据 | 从零开始积累，无迁移需求 |
| 状态模型 | 书/影均为**四态**：想读·在读·读完·**放弃** / 想看·在看·看完·**放弃** |
| 列表筛选 | 按**类型**筛选为主，辅以状态/搜索/排序 |
| 二刷/重温 | **不做**；预留"随时修改评分与评价"能力 |
| 基础统计 | 含**本年共阅读/观看**数量 |
| 封面展示 | 引用外部 URL；列表/卡片**默认直观显示封面**，加载失败有占位降级 |
| 数据导出 | 支持全量导出（CSV / JSON） |
| 访问保护 | **无需登录/口令**（单用户直接访问；公网链接请自行注意隐私） |
| 部署方式 | Vercel 托管 + 第三方云数据库 |

## 三、功能需求

### 3.1 必备功能（MVP）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 条目录入 | 书籍/影视新增：输入书名/片名 → 自动补全元数据 → 确认保存；补全失败转手动填写 |
| F2 | 条目管理 | 查看详情、编辑、删除 |
| F3 | 状态管理 | 书籍：想读 / 在读 / 读完 / **放弃**；影视：想看 / 在看 / 看完 / **放弃**；状态可随时流转 |
| F4 | 评分与评价 | ① 个人十分制评分 + 短评/备注，**保存后可随时修改**；② **豆瓣评分**字段（录入时自动获取，客观参考，获取失败可手动填写） |
| F5 | 类型筛选 | 按类型（分类）筛选列表，类型支持预置 + 自定义 |
| F6 | 搜索与排序 | 标题/作者关键词搜索；按评分、时间、标题等排序 |
| F7 | 基础统计 | 总量、状态分布、类型分布、**本年共阅读/观看数量** |

### 3.2 进阶功能

| 编号 | 功能 | 说明 |
|---|---|---|
| F8 | 统计图表 | 月度/年度新增趋势、评分分布直方图、类型均分对比、年度 Top 榜 |
| F9 | 年度目标 | 设置年度目标（读完 X 本 / 看完 X 部），环形进度展示 |
| F10 | 笔记 | 条目级笔记/摘录/读后感（**纯文本起步，数据结构预留富文本升级**） |
| F11 | 数据导出 | 全量导出 CSV / JSON，含评分、评价、笔记 |
| F12 | 标签 | 除类型外，支持自由标签归类 |

### 3.3 明确不做（范围控制）

- ❌ 社交分享、评论、社区化功能
- ❌ 二刷/重温的多条记录（仅支持修改单条记录）
- ❌ 多用户与协作
- ❌ 在线抓取后的人工校对平台（仅做一次性补全）
- ❌ 移动端原生 App（预留响应式适配）
- ❌ 登录/访问保护（v0.2 确认不需要）

## 四、信息架构与页面结构

```
┌─ 仪表盘 Dashboard         全局概览：统计卡片（含本年完成数）、近12月趋势、年度目标进度、最近添加
├─ 书籍库 Books             列表 + 筛选栏（类型 / 状态 / 搜索 / 排序）+ 卡片/列表视图切换（卡片默认含封面）
├─ 影视库 Movies            同上
├─ 条目详情页 Detail        元数据、个人评分 + 豆瓣评分、评价、笔记、编辑/删除入口
├─ 新增录入 Add（弹窗）     自动补全搜索框 → 补全结果确认 → 保存
├─ 统计页 Stats             评分分布、类型分布、月度趋势、年度 Top 榜
└─ 设置页 Settings          导出数据、备份说明、关于
```

**关键交互原则**

- **录入 ≤ 30 秒**：补全命中时只需 1 次确认即可保存；
- 录入入口全局可达（页面角落常驻"+"按钮）；
- 状态流转在列表卡片上可直接操作（如"读完"一键打勾），不必进详情页；
- **封面是列表卡片的第一视觉元素**：卡片视图默认大图封面 + 标题 + 评分，保证每次访问直观可见。

## 七、自动补全设计（重点）

### 7.1 元数据数据源建议

| 类别 | 首选 | 兜底 | 说明 |
|---|---|---|---|
| 书籍 | Google Books API | OpenLibrary API | Google 中文覆盖较好；OpenLibrary 无需 Key，ISBN 精确 |
| 影视 | TMDB API | — | 需注册免费 API Key；国际影视全，国产片覆盖一般 |

> 全部为**公开 API 调用**，不做爬虫、不抓取豆瓣，规避稳定性与合规风险。

### 7.2 补全字段

书名/片名 → 封面、作者/导演、简介、类型、年份等。

### 7.3 降级策略（关键体验）

- 补全命中：展示候选列表（含封面缩略），用户选择后填充表单；
- 补全失败：核心字段（标题）手动填写即可保存，其余字段留空、后续可编辑；
- 网络异常不阻塞录入——**任何情况下都能录进去**。

### 7.4 豆瓣评分获取说明（新增，需知悉）

> ⚠️ **现实约束**：豆瓣**没有开放官方 API**。"自动获取豆瓣评分"仅能通过非官方途径实现，存在不稳定、接口变动、合规等风险，无法保证 100% 拿到评分。

**设计策略：尽力自动 + 手动兜底**

1. 录入流程中，在元数据补全完成后**尝试**获取豆瓣评分（按「书名/片名 + 作者/导演」在非官方源检索）；
2. 获取成功 → 自动填入 `douban_rating`，用户可确认或修改；
3. 获取失败 / 源不可用 → 字段留空，**用户可手动填写**（豆瓣评分是客观参考，手动填一次并不费力）；
4. 该字段**永不阻塞保存流程**。

> 若后续你希望增强自动获取的稳定性，可评估第三方聚合服务（付费/需注册），作为 M3 之后的可选优化项。

## 八、非功能需求

| 项 | 要求 |
|---|---|
| 数据安全 | 数据库自动备份；支持一键全量导出；个人数据不外泄 |
| 性能 | 列表流畅（分页/虚拟滚动），首屏 < 2s |
| **封面可用性** | 引用稳定 CDN 图源（Google Books / TMDB）；**加载失败显示占位图**（含标题首字，保证视觉完整）；封面在列表卡片默认可见 |
| 可用性 | 录入 ≤ 30 秒；移动浏览器基本可用 |
| 部署 | Vercel 托管（Serverless）+ 第三方云数据库 |
| 隐私 | 不收集任何分析数据；无登录保护，公网链接即数据入口，请勿分享链接 |

## 九、技术选型建议

> ⚠️ **重要变更说明**：原设想为 React + Express + SQLite。但 **Vercel 为 Serverless 无状态环境，无法承载 SQLite 文件型数据库**（实例随时销毁、文件不持久）。因此数据库须迁移至**云数据库**。

### 9.1 架构建议

```
Vercel（Next.js）
  ├── 页面与交互（React）
  ├── Serverless API（Next.js API Routes / Route Handlers）
  └── 调用外部 API（TMDB / Google Books 补全，Key 存服务端环境变量）
云数据库（推荐 Supabase）
  └── Postgres 存储 + 可视化后台 + 备份
```

### 9.2 技术栈对比

| 方案 | 类型 | 免费层 | 优点 | 建议 |
|---|---|---|---|---|
| **Supabase** | Postgres | 500MB + Auth | 全托管、自带可视化后台与备份、生态成熟 | ⭐ 首选 |
| Neon | Serverless Postgres | 500MB | 纯数据库、弹性伸缩 | 备选 |
| Turso | 云 SQLite | 500MB | 保留 SQLite 心智 | 若坚持 SQLite 语法的备选 |
| PlanetScale | MySQL | 已调整 | — | 不推荐 |

- **前端/框架**：Next.js（Vercel 原生支持，API 一站式，开发体验好）；图表用 Recharts 或 ECharts；
- **认证**：v0.2 确认**无需登录**，单用户直接访问；
- 最终选型以确认后实施验证为准。
