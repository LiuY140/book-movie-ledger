## 第一步：初始化 Supabase 数据库（约 5 分钟）

### 目标
在 Supabase 云端创建 4 张表（books / movies / yearly_goals / settings）+ 枚举类型 + 触发器。

### 操作步骤

1. **打开 Supabase Dashboard**
   - 浏览器访问：https://supabase.com/dashboard
   - 用你注册的账号登录

2. **进入你的项目**
   - 在项目列表中点击你的项目（URL 中含 `jxpetflkciuldbpuayne` 的那个）

3. **打开 SQL Editor**
   - 左侧导航栏点击 **SQL Editor**（图标像一个 `>_`）
   - 点击 **+ New query**（新建查询）

4. **粘贴建表脚本**
   - 打开项目中的 `supabase/schema.sql` 文件
   - **全选复制**文件内容（Ctrl+A → Ctrl+C）
   - 粘贴到 Supabase SQL Editor 的输入框中（Ctrl+V）

5. **执行**
   - 点击右下角 **Run** 按钮（或按 Ctrl+Enter）
   - 等待执行完成，底部应显示 `Success`，无报错

6. **验证**
   - 左侧导航栏点击 **Table Editor**
   - 你应该能看到 4 张表：
     - `books` — 空表，有列定义
     - `movies` — 空表，有列定义
     - `yearly_goals` — 有 1 行数据（2026 年目标：30 本书 / 20 部影视）
     - `settings` — 有 1 行数据（默认分类配置）
   - 点击 `yearly_goals` 表，确认能看到 `2026 | 30 | 20` 这行

### 如果报错
- 报 `already exists`：说明之前跑过，在 SQL Editor 开头加 `DROP TABLE IF EXISTS books, movies, yearly_goals, settings CASCADE; DROP TYPE IF EXISTS book_status, movie_status CASCADE;` 然后重新 Run
- 其他报错：把错误信息发给我

## 第二步：启动开发服务器（约 1 分钟）

### 目标
在本地跑起来 Next.js 开发服务器，确认页面骨架正常。

### 操作步骤

1. **打开终端**
   - 在项目根目录 `E:\WorkBuddy\个人书影管理平台` 打开终端
   - （VS Code 中按 Ctrl+` 打开集成终端，或用 Windows Terminal / Git Bash）

2. **启动开发服务器**
   ```bash
   npm run dev
   ```

3. **等待启动完成**
   - 终端会显示类似：
     ```
     ▲ Next.js 14.x.x
     - Local:   http://localhost:3000
     ✓ Ready in 1.2s
     ```

4. **浏览器打开**
   - 访问 http://localhost:3000
   - 你应该看到：
     - 左侧墨绿色侧边栏，含「仪表盘 / 书籍库 / 影视库 / 统计 / 设置」5 个导航项
     - 主区域显示 Dashboard 骨架页面
     - 点击侧边栏各项，页面切换正常

5. **验证各页面**
   - http://localhost:3000/books — 书籍库骨架
   - http://localhost:3000/movies — 影视库骨架
   - http://localhost:3000/stats — 统计页骨架
   - http://localhost:3000/settings — 设置页骨架

### 如果报错
- `EADDRINUSE`：端口 3000 被占用，改用 `npm run dev -- -p 3001` 启动到 3001 端口
- 页面白屏：打开浏览器 F12 控制台，把报错信息发给我

## 第三步：推送到 GitHub（约 5 分钟）

### 目标
把项目代码推送到 GitHub 仓库，建立版本管理。

### 操作步骤

1. **在 GitHub 创建仓库**
   - 浏览器访问 https://github.com/new
   - **Repository name**：填一个你喜欢的名字，比如 `book-movie-platform`
   - **Description**（可选）：`个人书影管理平台`
   - **可见性**：选 **Private**（私人仓库，保护你的数据）
   - **不要勾选** "Add a README" / "Add .gitignore" / "Choose a license"（项目里已经有了）
   - 点击 **Create repository**

2. **复制仓库地址**
   - 创建完成后页面会显示类似：
     ```
     https://github.com/你的用户名/book-movie-platform.git
     ```
   - 复制这个地址

3. **在项目目录初始化 Git**
   打开终端，依次执行：
   ```bash
   cd "E:/WorkBuddy/个人书影管理平台"

   # 初始化 Git 仓库
   git init

   # 添加所有文件（.gitignore 会自动排除 node_modules、.env.local 等）
   git add .

   # 首次提交
   git commit -m "feat: 项目骨架搭建完成"
   ```

4. **关联远程仓库并推送**
   ```bash
   # 把下面的地址换成你自己的
   git remote add origin https://github.com/你的用户名/book-movie-platform.git

   # 推送到 GitHub
   git branch -M main
   git push -u origin main
   ```

5. **验证**
   - 刷新 GitHub 仓库页面，应该能看到所有项目文件
   - 确认 `.env.local` **不在** GitHub 上（被 .gitignore 排除了，包含你的密钥）
   - 确认 `node_modules/` **不在** GitHub 上

### 如果报错
- `git: command not found`：需要安装 Git，从 https://git-scm.com/download/win 下载安装
- 推送时要求登录：Windows 会弹出 GitHub 登录窗口，用你的 GitHub 账号登录即可
- `rejected - non-fast-forward`：`git push -u origin main --force` 强制推送一次

## 第四步：开始 M1 MVP 开发

### 目标
按优先级逐步实现核心功能，让平台从「骨架」变成「可用」。

### 开发顺序（每完成一个就可以测试）

```
① 数据层 CRUD  →  ② 录入弹窗  →  ③ 列表页接通数据  →  ④ 状态流转  →  ⑤ 详情页  →  ⑥ 导出
```

### ① 数据层 CRUD（最先做）
- 创建 `src/lib/books.ts`：封装书籍的增删改查（用 Supabase 客户端）
- 创建 `src/lib/movies.ts`：封装影视的增删改查
- 包含函数：`getAll()` / `getById()` / `create()` / `update()` / `remove()` / `updateStatus()`

### ② 录入弹窗
- 创建 `src/components/AddItemModal.tsx`
- 功能：输入标题 → 调用 `/api/search/books` 或 `/api/search/movies` 自动补全 → 选择结果填充表单 → 也可手动填写
- 保存到 Supabase

### ③ 列表页接通数据
- 改造 `src/app/books/page.tsx`：从 Supabase 拉取书籍列表，渲染卡片
- 改造 `src/app/movies/page.tsx`：同上
- 实现筛选（按类型 / 状态）和搜索

### ④ 状态流转
- 卡片上加状态切换按钮（想读 → 在读 → 读完 → 放弃）
- 调用 `updateStatus()`，数据库触发器自动维护时间线

### ⑤ 详情页
- 改造 `src/app/detail/[type]/[id]/page.tsx`
- 展示完整信息 + 编辑 + 笔记区域

### ⑥ 导出功能
- 在设置页添加「导出 CSV」「导出 JSON」按钮
- 服务端 API 路由生成文件并下载
